# AI API Integration Screenshots Guide — Practical 13

This guide details the required screenshots for lab journal submission demonstrating Practical 13 (OpenAI API integration with graceful degradation).

---

### Screenshot 1: Backend Environment Configuration (`.env`)
- **Where**: Open `backend/.env` in VS Code.
- **What to capture**:
  - `PORT=5000`
  - `MONGO_URI=mongodb://localhost:27017/taskdb`
  - `JWT_SECRET=...`
  - `OPENAI_API_KEY=sk-...` (⚠️ **CRITICAL**: Blur or redact the secret token characters, leaving only the `sk-` prefix visible).
- **Caption**: `Figure 13.1: Backend environment variables showing OPENAI_API_KEY securely configured (redacted)`.

---

### Screenshot 2: AI Suggest Button & Generated Description in UI
- **Where**: Frontend `http://localhost:5173/tasks` (logged in as an authenticated user).
- **What to capture**:
  - The Task Manager create form.
  - Title entered: e.g. `Implement OAuth2 Login Flow`.
  - The **✨ AI Suggest** button in purple gradient style.
  - The auto-populated description generated by `gpt-4o-mini`.
  - The disclaimer underneath: *"AI-generated — please review and edit."*
- **Caption**: `Figure 13.2: AI task description generation via OpenAI gpt-4o-mini with provenance disclaimer`.

---

### Screenshot 3: Graceful Degradation / Fallback on Invalid Key or Network Error
- **Where**: Frontend `http://localhost:5173/tasks` with an invalid API key in `backend/.env`.
- **What to capture**:
  - Click **✨ AI Suggest**.
  - The red error notice below the inputs: `AI unavailable, please type manually.`
  - Shows that the application does not crash and the user remains free to enter task details manually.
- **Caption**: `Figure 13.3: Graceful fallback handling when external AI service is unreachable or unauthorized`.

---

### Screenshot 4: Security Verification — `.gitignore` Excludes `.env`
- **Where**: Open `.gitignore` and `backend/.gitignore` in VS Code.
- **What to capture**:
  - The lines explicitly ignoring `.env`, `.env.local`, and `.env.*.local`.
  - The exception rule allowing template documentation: `!.env.example`.
- **Caption**: `Figure 13.4: Repository .gitignore ensuring secret keys are never committed to version control`.
